States

Idle / locked Station not yet reachable; prior steps incomplete.
Active Currently running. Border pulses; phase color tints the box.
Done Completed; artifact produced. Outgoing arrow turns green.
NO-GO / fixing /ship returned NO-GO. Phase D fixes loop back to /build, not /ship.

UX choices encoded in this mockup

  • Two-tier hierarchy. Define rail at the top (global, runs once) is visually separate from per-feature lanes — users can see "one global definition, many parallel features" without scrolling.
  • Lane starts at /spec. Every lane begins with a per-feature /spec station. The "Add Feature" button creates a new lane that pulses into existence at /spec, making re-entry visible.
  • Build ↔ Verify is one composite station with a visible loop. The dashed border, ⟳ icon, and iteration counter teach the model that build-test-debug is a cycle, not a straight line.
  • Review is a composite station, expandable. Click to reveal its four sub-steps (/review, /code-simplify, security, performance). Default collapsed keeps the lane scannable.
  • NO-GO is a backwards arrow to /build, not a hidden state. Lane #4 shows the loop drawn underneath, with the Phase D fix count visible.
  • Artifact track makes the chain explicit. SPEC → plan → todo → coverage → review → ship-decision under each lane, with the active artifact highlighted.
  • Phase colors map consistently. Define=blue, plan=orange, build=amber, verify=teal, review=purple, ship=green, NO-GO=red. Active stations tint with their phase; idle stations are neutral.
  • State markers are tiny corner badges (○ idle, ● active, ✓ done, ! NO-GO), so state is visible at a glance without crowding the station label.
